# Design: 視覺層次與命名調整

## Context

目前 IndividualPage / PortfolioPage 的結果區塊：

- 主要結論、中間指標、基礎統計、計算步驟以幾近相同的視覺權重呈現
- 區塊名稱使用技術術語（VaR、Monte Carlo），對非金融背景使用者不友善
- 區塊順序為 `EV → MC → VaR → Hurst`，但 MC 是「未來推估」性質，與 EV/VaR/Hurst 的「現況指標」混在一起
- 軌道分隔線（「── 風險頻率軌道 ──」）在當前順序下作用是區分月頻 vs 日頻，但若把 MC 移走後就失去了分組意義

## Goals / Non-Goals

**Goals:**
- 三層視覺層次清晰：Hero 結論 > 中層指標 > 弱化細節
- 區塊名稱用「動詞 / 名詞詞組描述用途」+ 副標保留技術名
- 區塊順序反映認知流程：現況指標 → 未來推估 → 行動建議
- IndividualPage 與 PortfolioPage 同步處理，維持兩頁體驗一致
- 計算步驟預設摺疊，需要才展開
- 不改任何計算邏輯或 API

**Non-Goals:**
- 不重新設計圖表（VarHistogram / FanChart / HurstLineChart 不變）
- 不引入新色彩 token
- 不調整 ComparePage（結構與其他兩頁差異大，下次再評估）

## Decisions

### D1 — 區塊順序與軌道分隔線移除

**決策**：新順序為「EV → VaR → Hurst → MC → ActionGuide」，移除原本的「軌道分隔線」，改為在每個區塊副標附加頻率標注。

```
[EV 區塊]            副標：使用月報酬 N 筆
[VaR 區塊]           副標：使用日報酬 N 筆 / 月報酬 N 筆
[Hurst 區塊]         副標：日報酬 240 日（多尺度 60/120/240）
[未來資產淨值模擬]    副標：使用月報酬 N 筆，初始 100 萬，模擬 100 條路徑
[ActionGuide]
```

**理由**：
- 「現況指標（EV/VaR/Hurst）→ 未來推估（MC）→ 行動建議（ActionGuide）」反映分析流程
- MC 在認知上是「假設未來資產走勢」，屬於補充資訊；放在 ActionGuide 前可避免被建議行動隔斷，但不應與現況指標混在一起
- 副標頻率標注比軌道分隔線更輕量，使用者只在需要時才注意到頻率資訊

**替代方案考慮**：
- MC 放整頁最下（在 ActionGuide 之後）：ActionGuide 是「綜合建議」應放最後，MC 在它之後語意奇怪，拒絕
- 保留軌道分隔線、改文字：MC 移走後分隔意義弱，改文字反而誤導，拒絕

### D2 — Hero 列的呈現方式

**決策**：每個分析區塊頂部新增 Hero 列，採「大數字 + 標籤 + 結論文字」三欄佈局。

```
┌─────────────────────────────────────────────────┐
│ ┌──────────────┐  象限徽章（large）            │
│ │ 期望值 EV    │  🏆 高賠率正期望值（最佳）   │
│ │ 0.47%        │                                │
│ │ (text-display│  賠率優勢：有優勢              │
│ │  字級加粗)   │                                │
│ └──────────────┘                                │
└─────────────────────────────────────────────────┘
```

**樣式**：
- 整列背景：較深的 elevated bg（如 `bg-blue-50` / `bg-red-50` 等依結論性質）
- 主數字：`text-display` (36px) + `font-extrabold`
- 配色（綠/紅）暗示方向：EV 正/負、VaR 風險高/低、MC 5 年 P50 vs 初始

**理由**：使用者掃過頁面瞬間就能抓到結論，配色提供方向訊號。

### D3 — ResultCard 的 emphasis prop

**決策**：在 `ResultCard` 新增 `emphasis: 'hero' | 'normal' | 'muted'` prop。

| emphasis | 字級 | 配色 | 邊框 | 用途 |
|----------|------|------|------|------|
| `hero` | text-display 加粗 | 較深底色 + 深字 | border-2 | 主要結論值 |
| `normal` | text-h1（既有）| 既有 | border | 一般指標 |
| `muted` | text-body | text-dim | 無底色 | 基礎統計 |

**保留 `large` prop**：作為 `emphasis="hero"` 的 alias，向後相容既有呼叫。

### D4 — 計算步驟改為 Disclosure（摺疊）

**決策**：EV 區塊的計算步驟改用 React state 控制的可摺疊區塊，**預設收合**。按鈕標籤「▶ 展開計算步驟 / ▼ 收折計算步驟」。與 VarBlock / HurstBlock 既有 `useState` 行為一致。

### D5 — 各區塊的「結論摘要列」內容

**決策**：

| 區塊 | Hero 主數字 | Hero 副資訊 |
|------|------------|------------|
| 期望報酬與賠率優勢 | 期望值 EV（%） | 象限徽章（large）+「賠率優勢」結論 |
| 下行風險 | VaR 95%（%） | 風險等級判讀（low/mid/high）+ 副標頻率 |
| 趨勢延續性偵測（Multi-Scale）| 已有 divergence 橫幅 | 沿用既有設計（不變） |
| 趨勢延續性偵測（單尺度，PortfolioPage 用）| Hurst H 值 | 解讀文字（趨勢/隨機/回歸）+ 副標頻率 |
| 未來資產淨值模擬 | 5 年 P50（萬） | 「期望範圍 P5: x 萬 ~ P95: y 萬」副標 |

### D6 — 弱化基礎統計的具體做法

**決策**：「基礎統計」區塊改為一個緊湊的 inline 行：

```
基礎統計
─────────────────────────────────────────
勝率 58.33% · 敗率 40.83% · Avg Gain 4.71% · Avg Loss 5.59%
```

- 字級 `text-small`、標籤 `text-faint`、數值 `text-dim`
- 移除底色塊，僅靠文字層次區分
- 不再使用 ResultCard 包裝

### D7 — PortfolioPage 對齊原則

**決策**：PortfolioPage 套用與 IndividualPage 相同的命名、順序、視覺層次規則。差異點：

- Portfolio 沒有象限徽章 → EV Hero 列只顯示「組合 EV + 副標」
- Portfolio 使用單尺度 Hurst（不是 multi-scale）→ Hurst 區塊 Hero 列為「H 值 + 解讀文字」
- 區塊命名前綴可加「組合」字樣（如「組合期望報酬與賠率優勢」），讓使用者區分頁面

**理由**：兩頁屬於同一產品線，UX 模式應該對齊。

### D8a — PortfolioPage 輸入區塊位置與摺疊

**決策**：把「股票選取與比重設定」區塊從頁面最下方移到最上方（緊接頁面標題下方），並包成可摺疊容器。預設行為：

- **未完成輸入**（任一股未選 / 權重不為 100%）→ 預設展開
- **已完成輸入且結果可顯示**（`ready === true`）→ 預設收合，讓結果聚焦
- 使用者可隨時手動切換

**實作**：
- 用 `useState(initialOpen)` 控制；`initialOpen = !ready`（首次計算）
- 後續 `ready` 變化不再強制覆寫使用者選擇（避免使用者展開後又被自動收合）

**理由**：
- 使用者完成設定後通常想看結果，輸入區塊就讓出視覺空間
- 仍要修改時點一下展開即可，比往下捲整頁更便利
- 與既有 VarBlock / HurstBlock 摺疊互動模式一致

**替代方案考慮**：
- 永遠展開：佔用版面，違背「結論優先」原則，拒絕
- 永遠收合：第一次使用者不知道要先選股，拒絕
- 用 ready 雙向綁定：使用者操作會被覆寫，UX 卡頓，拒絕

### D8 — 命名規則

**決策**：每個標題遵守三條規則：

1. 主標：用「動詞 / 名詞詞組描述用途」，避免縮寫單獨出現
2. 副標：保留學術名稱供懂技術的使用者對照（如「VaR 95% / 99%」「Hurst 指數，60/120/240 日」）
3. 副標附加資料來源頻率（如「使用日報酬 252 筆」）

## Risks / Trade-offs

- **使用者習慣 EV 計算步驟總是顯示**：摺疊後可能短暫不適應 → 緩解：摺疊按鈕用「▶ 展開計算步驟」明顯文字
- **PortfolioPage 與 IndividualPage 命名相似但不完全相同**：使用者可能誤認為同一頁 → 緩解：頁面標題本身已不同（「個股期望值計算」vs「投資組合分析」），加上「組合」字樣前綴強化區分
- **MC 移到 ActionGuide 之前**：使用者習慣 MC 緊跟 EV 後可能短期不適應 → 緩解：副標頻率標注 + 順序更符合「現況→推估→建議」邏輯
- **Hero 列配色依結論性質切換**：邊界值（如 EV 接近 0）可能視覺誤導 → 緩解：沿用既有 `color={x >= 0 ? 'green' : 'red'}` 簡單規則，不引入中性區
- **改動範圍橫跨兩個 page + 兩個共用元件**：合併測試成本提高 → 緩解：分批 commit / 分批驗證（先 ResultCard 升級 → IndividualPage → PortfolioPage）
