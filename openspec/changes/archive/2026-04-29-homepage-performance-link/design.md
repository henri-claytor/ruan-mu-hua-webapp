# Design: HomePage 補上績效分析入口

## Context

HomePage 是新使用者進站的第一個頁面，工具卡片決定他們認識哪些功能。目前 3 張卡只展示前向分析，績效分析（後向）必須從 NavBar 發現——對首次造訪者不友善。

## Goals / Non-Goals

**Goals:**
- HomePage 完整呈現 4 個分析工具
- 用視覺分組（前向 / 後向）傳達「投資閉環」概念
- 文案更新反映新功能能力
- 改動只動 HomePage 一個檔案，最小範圍

**Non-Goals:**
- 不重新設計整個首頁（不動 hero 字級、配色、整體 layout）
- 不加動畫、互動效果
- 不重構卡片元件

## Decisions

### D1 — 視覺分組結構

**決策**：用 H2 標題分兩組，前向 3 張一行（既有 grid-cols-3 不變），後向 1 張獨佔一行。

```jsx
<section>
  <h2>進場前評估</h2>
  <div className="grid md:grid-cols-3 gap-4">
    {forwardTools.map(...)}
  </div>
</section>

<section>
  <h2>出場後反思</h2>
  <div className="grid md:grid-cols-1 gap-4">
    {backwardTools.map(...)}  // 1 張
  </div>
</section>
```

**理由**：
- 分組讓使用者瞬間理解「兩種分析方向」
- 1 張卡獨佔一行可以更醒目地呈現新功能
- 不改既有 3 張卡的 layout，視覺上連續性高

**替代方案考慮**：
- 4 張一字排開（grid-cols-4）：失去概念分組
- 2x2 grid：4 張同等權重，無法強調「績效分析是新功能」

### D2 — 績效分析卡片內容

**決策**：

```typescript
{
  to: '/performance',
  Icon: Icon.ClipboardCheck,  // 既有 icon
  title: '績效分析',
  desc: '上傳已完成的交易紀錄，計算勝率、賠率、獲利因子；自動診斷打法品質與資金管理問題，可匯出 PDF / Excel 報告。',
  color: 'hover:border-purple-300 hover:bg-purple-50',  // 紫色與既有 3 張卡區隔
}
```

**色彩選擇**：紫色（既有 3 張為藍 / 綠 / 琥珀）。視覺上明確區分「這是不同類型的工具」。

### D3 — Hero 副標文案

**決策**：

```
進場前用市場資料評估標的；出場後用交易紀錄反思績效
一站式投資分析工具
```

**理由**：兩句結構強化「閉環」概念，第一句提兩個方向，第二句收斂為產品定位。

### D4 — 計算邏輯說明擴充

**決策**：grid 由 3 欄改為 4 欄（`md:grid-cols-2 lg:grid-cols-4`），加入「賠率與獲利因子」：

```
[ EV ]     [ VaR ]    [ Hurst ]   [ 賠率 / 獲利因子（NEW）]
EV = ...   VaR 95%    H = log    賠率 = Avg Gain / Avg Loss
           = 第 5     (R/S)/      獲利因子 = Σ獲利 / |Σ虧損|
           百分位     log(n)
```

**理由**：保留 4 個並列、字級一致；新增的「賠率 / 獲利因子」明確標示為績效分析專屬。

### D5 — 使用說明流程

**決策**：原 4 步驟保留（前向流程），加第 5 條獨立段落：

```
1. 選擇上方功能卡片，進入對應的分析工具
2. 在選股器輸入股票代號或名稱，系統自動載入月報酬與日報酬數據
3. 計算結果即時顯示於頁面，包含圖表與解讀說明
4. 使用「複製摘要」或「下載 PNG」按鈕匯出結果

—— 或 ——

5. 前往「績效分析」上傳已完成的交易紀錄（CSV 或手動輸入），系統自動產生勝率、賠率、獲利因子分析、4 象限診斷與 PDF / Excel 報告
```

**理由**：原前向流程 1–4 不動（避免破壞既有使用者習慣），第 5 條用「—— 或 ——」分隔線視覺上標示為「另一條路徑」。

## Risks / Trade-offs

- **新功能用紫色與既有色系不太一致**：可能視覺破碎 → 接受。績效分析屬於「不同種類」功能，色彩差異化反而幫助辨識
- **2x2 layout 在某些尺寸（如平板直立）可能擠**：4 欄計算說明 → 緩解：用 `md:grid-cols-2 lg:grid-cols-4` 適配
- **沒在 hero 區加大圖示說明閉環**：可能需要更多教育 → 接受第一版簡潔。未來如有需要可加流程圖
