# Design: Multi-scale Hurst

## Context

`calcHurst()` 接受任意長度的報酬序列，回傳單一 H 值。這個值代表了「該序列整段時間的平均長程相依性」。問題在於：

- **全期窗口稀釋了近期變化**：假設一支股票前 200 日 H = 0.7，最近 100 日 H = 0.4，平均下來看起來還是趨勢型（H ≈ 0.6），但實際上近期已轉為均值回歸
- **使用者無從判斷現在處於哪個 regime**：看到 H = 0.6 不知道是「長期趨勢加上近期延續」還是「長期趨勢但近期轉弱」

**約束條件**：
- R/S 分析在小樣本（< 50 筆）下統計誤差大，因此最短窗口需 ≥ 60
- 不能引入新依賴
- 計算量需可接受（三次 R/S 而非滾動 N 次）
- 只支援日頻：月頻資料的時間語意（每月一筆）與日頻不同尺度，混入會造成解讀混淆

## Goals / Non-Goals

**Goals:**
- 在不替換既有 `calcHurst()` 的前提下，新增 `calcMultiScaleHurst()` 提供短/中/長三尺度 H 值
- 自動偵測短期是否偏離長期，給使用者明確訊號
- UI 上以三張卡片並列呈現，附狀態判讀橫幅
- 保留長期 Hurst 的累積偏差圖（HurstLineChart）

**Non-Goals:**
- 不做 rolling Hurst（每天滾動算一次的時間序列），那會大幅增加計算與圖表複雜度
- 不對 PortfolioPage 套用（組合層級資料對齊問題複雜，等個股驗證後再決定）
- 不對 ComparePage 套用（兩股對比已用單一 H 值即可區分）

## Decisions

### D1 — 窗口大小選擇

**決策**：固定窗口、只支援日頻。

| 尺度 | 窗口大小 | 對應時間 |
|------|----------|----------|
| 短期 | 最近 60 筆日報酬 | 約 3 個月 |
| 中期 | 最近 120 筆日報酬 | 約 6 個月 |
| 長期 | 最近 240 筆日報酬 | 約 1 年 |

**最低資料量需求**：日報酬 ≥ 240 筆。不足則不顯示 `MultiScaleHurstBlock`。

**理由**：
- 60 / 120 / 240 = 3 個月 / 6 個月 / 1 年，時間尺度語意清晰且為整數倍關係
- 長期固定 240 而非「全期」：避免不同股票因資料長度不同（300 vs 400）導致 H 值口徑不一，影響跨股比較
- 不做月頻 fallback：月頻每筆代表一個月，60 月 = 5 年，與日頻 60 日（3 個月）的時間尺度語意完全不同，混入會造成解讀混淆。資料量不足時提示使用者，比給出語意混淆的結果更負責任

**替代方案考慮**：
- 月頻 fallback（短 12 / 中 24 / 長 60）：時間尺度與日頻不對等，捨棄
- 「最多 240」而非「固定 240」：跨股 H 值口徑不一，捨棄
- 90 / 180 / 360 日：短期 90 日對 regime change 反應較慢，捨棄

### D2 — Divergence 判斷規則

**決策**：以「短期 H 與長期 H 的差距」與「H 跨越 0.5 中性線」兩條件判斷：

| 狀態 | 條件 | 含義 |
|------|------|------|
| `stable` | `|H_short − H_long| ≤ 0.10` | 三者一致，狀態穩定 |
| `short-weakening` | `H_short < H_long − 0.10` 且 `H_short < 0.5 ≤ H_long` | 短期偏向均值回歸，長期仍趨勢 → 趨勢可能正在減弱 |
| `short-strengthening` | `H_short > H_long + 0.10` 且 `H_short > 0.5 ≥ H_long` | 短期動能轉強，長期偏均值回歸 |
| `mixed` | 其他差距 > 0.10 但未跨越 0.5 的情況 | 有差距但方向未明確翻轉 |

**理由**：
- 0.10 作為門檻是經驗值：R/S 分析在 60 筆日頻資料的標準誤約 0.05–0.08，0.10 差距具備統計意義
- 0.5 中性線跨越是 regime change 的關鍵訊號（趨勢↔均值回歸的分界）
- 四個狀態足以涵蓋使用者最關心的場景，不過度細分

**替代方案考慮**：
- 用統計顯著性檢定（bootstrap 信賴區間） → 計算量大且結果難向使用者解釋，拒絕
- 只分 stable / unstable 兩類 → 失去方向資訊（變強 vs 變弱），拒絕

### D3 — UI 呈現策略

**決策**：在 IndividualPage 用 `MultiScaleHurstBlock` 完全取代原 `HurstBlock`。結構：

```
┌──────────────────────────────────────────────────┐
│ Hurst 多尺度分析                                │
│  使用日報酬 252 筆 / 月報酬 120 筆               │
├──────────────────────────────────────────────────┤
│  [狀態判讀橫幅]                                  │
│  ⚠ 短期偏離長期：趨勢可能正在減弱                │
├──────────────────────────────────────────────────┤
│  [短期 60日]   [中期 126日]   [長期 全期]        │
│      0.42         0.55           0.65            │
│   均值回歸       中性            趨勢             │
├──────────────────────────────────────────────────┤
│  [HurstLineChart] (顯示長期窗口的 Xₜ)           │
├──────────────────────────────────────────────────┤
│  [計算步驟] (顯示長期窗口的 R/S)                 │
└──────────────────────────────────────────────────┘
```

**理由**：
- 三張卡片並列在視覺上比折線圖更直觀，差異一眼可見
- 狀態判讀橫幅放最上方，第一時間給結論
- HurstLineChart 與計算步驟只顯示「長期」窗口，避免三組重複資訊轟炸使用者

**替代方案考慮**：
- 三組各自畫 HurstLineChart → 資訊密度過高，拒絕
- 用三條折線疊加在同一張圖 → 三個窗口長度不同，X 軸難對齊，拒絕

### D4 — ActionGuide 整合

**決策**：在 `buildIndividualGuide` 的訊號中新增 `hurstDivergence?: Divergence`。當為 `short-weakening` 或 `short-strengthening` 時插入提示訊息。原本的「Hurst 解讀」規則改為使用**短期 H**（更貼近當下狀態）。

**理由**：使用者拿建議就是要看「現在該怎麼做」，短期 H 更具行動性。

## Risks / Trade-offs

- **短期 60 筆 H 統計誤差較大** → 緩解：在卡片標題下加「樣本較小，誤差較大」提示；divergence 門檻 0.10 已留 buffer
- **日報酬不足 240 筆的股票無法使用** → 緩解：明確提示「需要約 1 年交易紀錄」，使用者可改看單尺度 Hurst（既有的 `calcHurst()` 仍可運作）
- **既有 `calcHurst()` 不再被 IndividualPage 直接使用** → 保留以向後兼容（`hurst.test.ts` 既有測試不變動），但個股頁完全改用 `calcMultiScaleHurst`
- **使用者可能誤以為「短期偏離 = 立即進出場訊號」** → 緩解：橫幅文案使用「可能正在減弱」「可能轉強」等推測性語氣 + ActionGuide 既有免責聲明
- **與既有 `calcHurst()` 重複邏輯** → 接受。`calcMultiScaleHurst()` 內部呼叫 `calcHurst()` 三次，DRY 由現有函式保證
